# 飞划 APS 用户手册

面向计划员、排程员、销售、生产主管的日常操作说明。

---

## 1. 登录与界面

打开系统地址，输入账号密码登录（默认 `admin` / `aps@2026`，**首次登录请立即改密码**）。

左侧为导航栏，共 9 个页面：

| 页面 | 谁用 | 干什么 |
|---|---|---|
| 仪表盘 | 所有人 | 一眼看清工单数、迟交数、未处理告警、负荷排名 |
| 排程与甘特 | 计划员/排程员 | 跑排程、看甘特图、插单 |
| 销售订单 | 销售/计划员 | 建订单、转工单 |
| 生产工单 | 生产/计划员 | 维护工单、改交期优先级 |
| 物料齐套 | 计划员/生产 | 算缺料、看哪几张单被卡 |
| 交期承诺 | 销售 | 查"这单最早什么时候能交" |
| 主数据 | 计划员 | 工作中心、物料、产品/BOM、工艺路线、库存调整 |
| 告警中心 | 所有人 | 处理迟交/超载/缺料告警 |
| 系统管理 | 管理员 | 用户、规则参数、API Key、审计日志 |

> 看不到的菜单 = 当前角色没这个权限，属正常。

## 2. 五分钟跑通一遍

新系统上线后，按这个顺序走一遍能迅速理解系统在干什么：

1. **主数据 → 工作中心**：确认 6 个工作中心的 `日产能` 和 `效率` 是真实的。
2. **主数据 → 工艺路线**：确认每个产品的工序顺序、工作中心、工时对不对。
3. **主数据 → 物料**：录入真实库存。
4. **排程与甘特 → 执行排程**：规则选 `EDD`，点下去。
5. **看结果**：甘特图上看每张单排在哪几天；下面的负荷榜看哪个中心快撑爆。
6. **物料齐套 → 执行齐套检查**：看哪几张单缺料。
7. **交期承诺**：拿一张潜在订单试试，看能不能接。

## 3. 排程与甘特

### 3.1 执行排程

工具条上选规则，点「▶ 执行排程」。

**四种规则怎么选？**

| 规则 | 什么时候用 |
|---|---|
| **EDD** 最早交期 | 默认。绝大多数情况用它 |
| **CR** 关键比率 | 交期松紧差得很大时。它会让"时间紧、活量大"的单自动插队 |
| **PRIO** 优先级 | 有明确客户分级、战略客户必须保时 |
| **FIFO** 先到先做 | 想减少换线、追求公平，或客户之间没有差别时 |

**技巧**：同一批工单可以连着跑两三次不同规则，对比"迟交几个、是哪几个"，再决定用哪个。每次跑都会生成一个新批次，历史批次不会丢。

### 3.2 看懂甘特图

- 横轴是时间（从排程起点开始 90 天）。
- 每一行是一个工作中心，条上标工单号。
- **颜色含义**：正常条为普通色；**红色条表示这张单会迟交**。
- 同一张工单的多道工序会出现在不同工作中心的行上，看它们是否前后衔接得上。

### 3.3 看懂负荷榜

每个工作中心一行：

```
WC-ASSY 总装线  ████████████████░░░░  78.2%（96.0h/512.0h）
```

- **利用率 > 100%**：超载，理论上不该出现（说明有人手工改过数据）。
- **≥ 90%**：黄色预警，这个中心快满了，是新订单的瓶颈。
- **排序第一且 ≥90%** 的那个中心，就是系统认定的瓶颈。

### 3.4 插单重排

急单来了，点「⚡ 插单重排」，填产品、数量、期望交期、优先级，确定。

系统会：
1. 自动建销售订单 + 工单
2. 立刻全量重排
3. 告诉你这张单**排到哪天完工**
4. 告诉你**因为插这张单，另外哪几张单变成迟交了**

第 4 点是谈判依据——可以拿着这个结果跟销售/客户说"接这单会让 A、B 两张单延迟"。

## 4. 物料齐套

### 4.1 执行检查

进「物料齐套」点「▶ 执行齐套检查」。

系统按**当前排程顺序**模拟发料（先排先领），逐单核对 BOM。

### 4.2 看懂结果

顶部三个数字：`齐套工单` / `缺料阻塞` / `物料品种`。

明细表每行一张工单：

- 绿色 `齐套`：料够，可以开工。
- 红色 `缺口 N`：缺 N 种料，右边列出具体缺口，格式 `物料 需X 存Y 缺Z`。

底部「缺口汇总」按物料汇总：这个料总共缺多少、卡住了哪几张单。

### 4.3 关键理解

**缺料工单不扣库存。** 意思是：如果某张单缺料，系统不会假装把库存扣掉，所以后面那些单不会因为"库存被前面吃光了"而被误判缺料。

这样算出来的库存余额才是真实的——真正会被消耗掉的量。

### 4.4 缺料了怎么办

看缺口汇总，按这个优先顺序处理：

1. **催料**：缺口小、供应商能给日期的，直接催。
2. **调序**：把不缺料的单往前排（用 PRIO 规则重跑），让产线先干活。
3. **拆单**：先做一部分，剩余等料。
4. **外协**：缺口大的关键件考虑外协。

## 5. 交期承诺（CTP）

### 5.1 什么时候用

销售接单前问"这单什么时候能交"，或者客户压交期时需要给准话。

### 5.2 怎么用

进「交期承诺」，选产品、填数量、填期望交期，点查询。

### 5.3 看懂结果

系统给三种答案：

| 结果 | 说明 | 怎么回客户 |
|---|---|---|
| **可按期承诺** | 排下来能在期望交期前完工 | 直接承诺 |
| **最早 X 完工，晚 N 天** | 能做，但比客户要的晚 | 报真实日期，或商量插单/加急 |
| **视界内排不下** | 90 天内都排不进去 | 建议拆单或外协 |

### 5.4 为什么这个日期可信

因为 CTP 不是估算，而是**真的把你的单插进去重排一遍**，用的是和正式排产完全相同的算法和产能约束。所以它给的日期，就是真排下去能完工的日期。

### 5.5 注意

- 一次 CTP 会占用一点计算时间（工单多时 1~2 秒），销售狂点没关系，但别当实时接口高频调用。
- CTP 结果会存历史，可以翻查"上次这个客户问的时候我们答的什么"。

## 6. 告警中心

### 6.1 四类告警

| 类型 | 什么时候出现 | 怎么办 |
|---|---|---|
| **工单迟交** | 排程结果显示完工日晚于交期 | 协商交期 / 插单加急 / 拆单 |
| **交期临近** | 距交期只剩几天（默认 3 天）缓冲不足 | 盯紧进度 |
| **中心超载** | 利用率 > 100% | 查是否手工改过数据 |
| **中心繁忙** | 利用率 ≥ 90%（默认） | 新单排产时避开这个中心 |
| **物料缺口** | 齐套检查有缺料 | 催料 / 调序 |

### 6.2 处理

每条告警右边有「处理」按钮，点完变为 `已处理`，从待办列表移除。

**建议**：每天上班第一件事刷一遍未处理告警。

## 7. 主数据维护

### 7.1 工作中心

| 字段 | 说明 | 填错的后果 |
|---|---|---|
| `日产能(h)` | 一天能干几小时 | 直接决定排程松紧 |
| `效率系数` | 0~1，实际稼动率 | 0.75 = 实际只有 75% 的产能 |
| `工作日` | 周几开工 | 排到不该开工的日子 |
| `类型` | 机加/装配/检验等 | 仅展示用 |

**技巧**：新设备效率填 1.0，老设备按实际稼动率填（比如 0.75~0.85）。这样排出来的图更贴近现实。

### 7.2 物料

`现有库存` 是齐套检查的基础。上线前一定要盘准，否则齐套结果全错。

### 7.3 工艺路线

每个产品的一道工序一行：

- `工序号`：10、20、30 递增，系统按此顺序串行排。
- `工作中心`：这道工序在哪台/哪条线做。
- `准备工时(h)`：开机调试、换模时间，每批一次。
- `单件工时(h)`：每个产品花多少小时。
- `转移时间`：填 >0 表示这道工序做完要等一天才能进下一道（如需要自然冷却、转运）。

**单工序总工时 = 准备工时 + 单件工时 × 数量**

### 7.4 库存调整

物料页有「库存调整」，正数入库、负数出库，会记审计日志。用于日常盘盈亏、到货入库。

## 8. 系统管理

### 8.1 业务规则

| 参数 | 作用 | 建议值 |
|---|---|---|
| `sched_rule` | 默认排程规则 | EDD |
| `late_warn_days` | 交期预警天数 | 3 |
| `util_warn` | 负荷预警线 | 0.9 |
| `horizon_days` | 排程视界 | 90 |

改完立即生效（下次排程开始）。

### 8.2 API 密钥

给 ERP、MES、BI 对接用。

**创建步骤**：
1. 点「创建 API Key」，起个名（如 "MES 集成"）
2. 选角色（按最小权限原则，MES 一般给 `prod`）
3. 点确定，**完整 key 只显示这一次**，立刻复制保存

**注意**：
- 列表里只显示前缀，看不到完整 key，忘了只能重建。
- 不用了就删掉，避免僵尸 Key。

### 8.3 审计日志

记录登录、排程、改主数据、改规则等关键操作，可查"谁在什么时候干了什么"。

## 9. 常见问题

**Q：为什么排出来的完工日期比标准工时算出来的晚很多？**
A：因为要考虑产能约束。如果工作中心已经排满了，新单只能等前面做完。这说明产线真的紧张，不是系统算错。

**Q：为什么仪表盘显示 10 个工单，但迟交只有 2 个？**
A：迟交是按排程结果判定的——只有完工日超过交期才算。剩下的 8 张都能按期完成。

**Q：甘特图上红色条是啥？**
A：会迟交的工单。

**Q：跑完排程，工单状态变了，手工还能改吗？**
A：`排产中` 的工单不能直接改回 `已下达`，防止绕过排程导致数据不一致。要调整请改主数据或走插单。

**Q：齐套检查说缺料，但仓库说料够？**
A：先查库里库存录入是否准确，再看是不是被排在前面的单领走了（先排先领）。看缺口汇总里的"阻塞工单"就知道谁领的。

**Q：CTP 说能按期，实际生产却迟了？**
A：CTP 只算排程可行性，不含异常停机、缺料、质量问题。它是"计划可行性判断"，不是"保票承诺"。建议在客户沟通时留一点缓冲。

**Q：改了效率系数，为什么排程结果没变？**
A：设置改了不会自动重排，要重新点「执行排程」。

**Q：能不能多个人同时跑排程？**
A：可以，但会互相覆盖批次（每次跑生成新批次）。建议指定专人负责排程，其他人只读。
